# Platform rules

Each software stack owns its shared adapter, runtime/build helpers, reusable components and simulation support. Concrete Targets live only in devices/<device>/targets/, including their BSPs, examples and board configuration. Tests and fixtures live under tests/, following [test ownership](../docs/development/testing.md). Do not add board directories or duplicate Device implementations here. Native peripheral interfaces live in target.json under interfaces; they are not cloud Skill Capabilities.

Adapters implement build, cases, probe and validate_target. Declare every operation in io_utils.OPERATIONS in platform.json, including firmware-plan, firmware-merge and firmware-verify. Platforms supporting firmware delivery also implement firmware_layout, firmware_merge and firmware_verify. Native layout parsing and image tools belong to the Platform; shared code owns receipts, provenance and publication. Missing tools mean not_run. Exact expected case coverage, Target identity, operation and source digest must match the result. Declare all native source inputs and dependencies, including per-example locks. New stacks need a real reference Target and adapter tests before board support can be claimed.
